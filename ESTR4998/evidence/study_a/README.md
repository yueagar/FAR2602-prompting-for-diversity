# Four-instruction comparison on DeepSeek (Study A)

From the repository root, run `python3 -B ESTR4998/evidence/study_a/reproduce.py`. This rebuilds the main effects in Table 10, the two automatic safeguards, and the saturation counts on the development tasks. It also adds up the study's recorded cost allocations. Python's standard library is sufficient.

[cells.csv](cells.csv) contains one row for each of 80 ten-response sets, with task aliases in the original analysis order. Counts of distinct groups use the original Gemini judgments. The quality columns give the sum of the ten scores and the number scoring 10. The constraint denominator is zero for tasks without an applicable constraint. [cost_by_arm_role.csv](cost_by_arm_role.csv) gives the number of submitted requests, known cost in USD and number with unknown cost in each of 12 allocations across instructions and roles.

The replay averages the two repetitions within each task, subtracts default from each alternative on that task and gives each task equal weight. It uses the analysis implementation in [api_report.py](../../api_study/api_report.py) for the original 5,000-draw paired task bootstrap. The 95% intervals are nominal. The quality guard covers ten tasks with a half-point margin. The constraint guard covers six applicable tasks with a five-percentage-point margin. Both guards concern automatic measures. Study A is exploratory and uses the development set.

The public input columns are numeric projections from the archived study result and report. The archived report had SHA-256 `883a541dd45868c1caa9d046564c30d4333d9d7e1ec623ad36f930285207715a` and recorded the source result hash. [reference.json](reference.json) records the comparison values from that report. The replay checks them to absolute tolerance 1e-12. The cost sum checks the published stage allocations, with each entry rounded to nine decimal places. Independent rescoring of individual replies and auditing individual invoices would require the original records.
